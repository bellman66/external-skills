## 왜 필요한가

Claude 가 코드를 쓰기 전에, 무엇을 만들 것인지 둘이 합의해야 한다. 그 합의는
결정의 트리이고, 대부분은 프롬프트에 없다 — 아직 둘 다 떠올리지 못한 가지에 있다.

그걸 대화로 캐내면 세 가지를 치른다.

- **긴 서두.** 첫 질문이 나오기 전에 맥락을 통째로 정비해야 한다.
- **표류.** 필요 없는 맥락이 따라 들어오고, 정작 필요한 맥락은 늦게 나온다.
- **기다림.** 묻고 답하고 다시 계획하고 또 묻는다. 왕복 한 번에 결정 하나.

tree 는 그 인터뷰를 창으로 옮긴다. 질문이 **레이어** 단위로 오고, 번호 키로
답하며, 모델은 질문마다가 아니라 레이어마다 한 번 불린다.

## 동작 방식

레이어란 선행 결정이 모두 해소되어 지금 물을 수 있는 결정들의 집합이다. 같은
레이어의 결정끼리는 서로의 답에 의존하지 않으므로, 한 화면에 펼쳐두고 아무
순서로나 답해도 된다.

```
/tree <무엇을 정할지 한 줄>
   │
   ├─ 모델 호출 1회 ──────────────► 1단계
   │
   ▼
┌─────────────────────────────────────────────┐
│ ▸ ● 저장 방식                   → SQLite    │  번호 키로 선택
│ ▾ ● 보존 기한                               │  아직 아무것도 안 보냄
│   ╭────────────────────────────────────╮    │
│   │ 언제까지 들고 있나?                │    │
│   │ 왜 묻나 · 삭제·해지 칸 비었음      │    │
│   │              ✓ 90일      ★추천     │    │
│   │              2 무기한              │    │
│   ╰────────────────────────────────────╯    │
│ ▸ ● 접근 권한                               │
└─────────────────────────────────────────────┘
   │
   ├─ [ 다음 단계로 ] ─ 모델 호출 1회 ───────► 2단계
   │                     · 고른 답은 확정
   │                     · 안 고른 것은 미뤄짐 (사라지지 않음)
   │                     · 모순되는 결정은 다시 열림
   │                     · 전제가 죽은 결정은 걷힘
   ▼
  … 더 물을 것이 없을 때까지
   │
   └─ [ Claude에게 넘기기 ] ───────────────► 작업 지시서
```

응답은 델타다 — 다음 레이어와 되돌리거나 걷어낼 id 목록일 뿐, 트리 전체를 다시
쓰지 않는다.

## 시작하기

```bash
git clone https://github.com/bellman66/external-skills
claude --plugin-dir ./external-skills/tree
```

세션에서:

```
/tree 결제 연동을 붙이고 싶다
```

인자를 생략하면 직전에 보낸 프롬프트를 씨앗으로 쓴다.

계속 쓰려면 다른 Claude Code 플러그인과 마찬가지로 디렉터리를 마켓플레이스로
추가해 설치한다.

## 창 쓰는 법

질문은 제목만 한 줄씩 깔리고 그중 하나가 펼쳐진다. 제목을 누르면 그게 열리고
앞의 것은 접힌다. **선택지 옆 번호가 곧 단축키다** — `1` 을 누르면 1번이 선택된다.
추천안은 `★추천` 으로, 고른 것은 초록 `✓` 로 표시된다.

| 키 | 버튼 | 하는 일 |
| :- | :- | :- |
| `a` | 전체 펼치기 | 이 단계의 모든 질문을 펼친다. 번호가 겹치므로 그동안 번호 단축키는 꺼진다 |
| `p` | 추천으로 모두 선택 | 안 고른 질문을 전부 추천안으로 채운다. 켜두면 새 단계도 자동으로 채워져, 다음 단계로만 누르면 끝까지 간다 |
| `s` | **다음 단계로** | 이 단계를 확정하고 다음 단계를 받는다. 다 고르면 테두리가 **굵어진다** |
| `m` | **메모 반영** | 방금 적은 메모에 맞춰, 다음으로 넘어가지 않고 지금 단계를 다시 만든다 |
| `r` | **Claude에게 넘기기** | 작업 지시서를 쓰고 창을 닫는다 |
| `l` | EN / 한국어 | 언어팩을 바꾼다 |
| `t` | 다시 시도 | 레이어를 받지 못했을 때 나타난다 |
| `c` | 그만 기다리기 | 호출이 나가 있는 동안 나타난다 |

답하지 않고 넘긴 질문은 **사라지지 않고 미뤄진다** — 회색으로 닫히고, 나중에
물어야 할 것으로 지시서에 이름이 남는다.

질문마다 선택지에 없는 답을 적는 입력칸과, 그 결정 하나에 조사 서브에이전트를
띄우는 **코드에서 찾아보기** 버튼이 있다.

## 신호등

| | 존 | 뜻 |
| :-: | :- | :- |
| 🔴 | unknown | 아직 안 정했다. 필요한지부터 열려 있다 |
| 🟡 | gray | 방향은 잡혔고 모호한 지점이 남았다 |
| 🟢 | known | 정했다 |
| ⚫ | deferred | 미뤘거나 걷어냈다. 둘 다 종료를 막지 않는다 |

## 확장 컨텍스트와 원하는 결과

질문 아래에 목록이 둘 있다. 둘 다 할 일 목록처럼 움직인다 — **`[ + 추가 ]`** 를
누르면 입력칸이 내려오고, Enter 하면 행이 되고, `x` 로 지운다. 동시에 열어둘 수 있다.

**확장 컨텍스트** 는 선택지로 담기지 않는 것을 적는 곳이다. 제약, 전제, 대화였다면
그냥 말했을 내용.

> 결제사는 하나로 묶여 있어 바꿀 수 없다.

열린 단계가 아직 읽지 않은 메모는 노란 `+` 로 표시되고 **메모 반영** 이 나타난다.
누르면 그 전제 위에서 단계가 다시 만들어진다 — 더는 해당 없는 질문은 걷히고,
모순되는 결정은 다시 열린다. 한 번 읽히면 전제로 내려앉아 계속 유효하되, 같은
질문을 반복해서 깨우지는 않는다.

**원하는 결과** 는 완성물이 만족해야 할 조건이다. 적으면 질문이 그쪽으로 좁혀지고,
지시서에는 체크리스트로 들어간다.

## 무엇이 넘어가는가

결정 목록이 아니다. 받는 쪽이 아무것도 되묻지 않고 바로 착수할 수 있는 작업
지시서다.

```markdown
# 작업 지시

## 하려는 일
결제 연동을 붙이고 싶다

## 전제 — 사용자가 못박은 것
- 결제사는 하나로 묶여 있어 바꿀 수 없다

## 확정된 결정

### 1. 연동 경로 → 게이트웨이 경유
- 물은 것: 결제사를 어떤 경로로 붙이나?
- 왜 물었나: 단일 결제사 결정에서 파생
- 그 선택을 고른 근거: 기존 웹훅·멱등 키 구조를 재사용할 수 있음

### 2. 보존 기한 → 30일
- 물은 것: 언제까지 들고 있나?
- 사용자가 선택지 대신 직접 적은 답이다

## 결과물이 만족해야 할 조건
- [ ] 배포 없이 되돌릴 수 있어야 한다

## 정하지 않은 것 — 물었지만 미룸
- 접근 권한 — 누가 볼 수 있나?

## 빼기로 한 것 — 전제가 바뀌어 무효가 됨
- 이전 결제사의 통화 처리

## 진행 방법
- 위 결정은 사용자와 이미 합의된 것이다. 다시 묻지 말고 그대로 전제하라.
- 전제와 결정이 어긋나 보이면 전제가 우선이다.
- 미룬 항목은 지금 결정하지 말고, 그 자리에 오면 사용자에게 물어라.
- 빼기로 한 항목은 고려 대상이 아니다. 되살리지 마라.
- 작업을 마친 뒤 조건 목록을 하나씩 짚어라.
```

**빼기로 한 것** 이 제 몫을 하는 절이다. 이게 없으면 다음 세션은 옛 결제사가
왜 없는지 모른 채 그걸 다시 제안한다.

## 비용

질문마다가 아니라 레이어마다 호출 한 번. 결정 13개짜리 인터뷰면 서너 번이고,
응답도 트리 전체가 아니라 다음 레이어뿐이다 — 질문 단위로 부르는 모양의 약 1/10.

호출은 `$.model.fork` 를 타므로 대화는 프롬프트 캐시에서 오고, 새로 실리는 것은
압축한 트리 스냅샷뿐이다. 포크는 메인 스레드가 한 번은 답했어야 가능한데
`/tree` 는 그렇지 않으므로, 첫 호출은 최근 메시지를 직접 실어 완결 호출로 넘어간다.

선택은 공짜다. 다음 단계로를 누르기 전까지 아무것도 보내지 않는다.

## 언어

한국어와 영어. `l` 로 바꾸고 세션을 넘어 기억된다. 창의 모든 문구, 명령 설명,
실패 사유, **모델이 질문을 쓰는 언어**, 그리고 작업 지시서까지 바뀐다.

팩은 `hooks/register.js` 의 객체 하나에 모여 있다. 언어를 더하는 일은 항목을
하나 더하는 일이다.

## 상태

트리는 `$.state` 에 있다 — **한 세션**. `/clear`, `/resume`, `/branch` 하면
초기화된다. 언어 설정은 `$.store` 에 있어 세션을 넘어 유지된다.

## 개발

```bash
claude plugin validate ./tree   # 이 mod 가 거는 훅과 호출 목록
cd tree && claude plugin test   # 44개, 세션도 네트워크도 필요 없음
```

테스트는 사람이 하듯 창을 조작한다 — 키로 버튼을 누르고, 입력칸에 치고, 그려진
것을 읽는다. 모델은 스텁이라 토큰 한 푼 쓰지 않고 레이어 동작, 비용 성질, 실패
복구, 지시서까지 검증한다.

`tsconfig.json` 은 `--plugin-dir` 로 로드할 때 Claude Code 가
`.claude-plugin/types/` 에 써주는 타입 선언을 extends 한다. 생성물이라 커밋하지
않으므로, 한 번 로드하면 `tsc` 가 동작한다.

## 한계

- 창은 터미널과 Desktop 앱에서만 그려진다. VS Code 확장, `claude -p`, 클라우드
  세션에서는 훅은 돌지만 아무것도 보이지 않는다 — 그 환경에서는 `grill-me`
  스킬을 쓴다.
- 트리는 `/clear` 를 넘기지 못한다. 지우기 전에 넘겨라.
- Claude Code 2.1.296 에서 작성했다.
